# NPSL format (`.npsl`)

NPSL — **N**euro**p**harmacology **S**andbox **L**ibrary — is the portable,
versioned, JSON-based library format of this project. File extension:
`.npsl`. Content type: JSON (UTF-8).

Normative implementation: `src/data/schemas/npsl.ts` (Zod). This document
explains the structure, the versioning policy and the evolution rules.

The `.npsl` file is an **interchange/backup format**. The live library lives
in IndexedDB; `.npsl` is how users back it up, share it and move it between
installations.

---

## 1. Top level

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `formatVersion` | semver string | yes | Version of the file envelope (top-level structure) |
| `schemaVersion` | semver string | yes | Version of the data schema (drugs, parameters) |
| `libraryMetadata` | object | yes | See §2 |
| `drugs` | array | yes | See §3 |

Both versions exist because they change independently: adding an optional
library-level field bumps `schemaVersion` minor; changing the envelope (e.g.
adding a top-level `checksum`) bumps `formatVersion` minor. Breaking changes
bump the major of the respective version.

### Version compatibility

A file is importable when:

- `formatVersion` and `schemaVersion` majors equal this build's majors, and
- their minors are ≤ this build's minors.

Otherwise the import is refused with an explicit message ("newer minor —
update the application"), never partially applied.
Implemented and unit-tested: `checkNpslVersions()` in `src/data/schemas/npsl.ts`.

## 2. `libraryMetadata`

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `id` | string | no | Generated by the importer when absent |
| `name` | string (≥1 char) | yes | Library display name |
| `author` | string | no | |
| `description` | string | no | |
| `createdAt` | ISO 8601 date-time | yes | |
| `updatedAt` | ISO 8601 date-time | yes | |
| `dataStatus` | enum | no (default `unspecified`) | `example` \| `sourced` \| `mixed` \| `user` \| `unspecified` |

`dataStatus` makes example/demo data explicit at the library level, as
required by the specification. A bundled demo library ships with
`"dataStatus": "example"` and its drugs carry `origin: "built-in-demo"`.

## 3. `drugs[]`

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `id` | string (≥1 char) | yes | Unique within the library |
| `origin` | enum | yes | `built-in-demo` \| `user` \| `imported` |
| `identifiers` | object | yes | `name` (required), `synonyms` (default `[]`), `description?`, `casNumber?` |
| `tags` | string[] | no (default `[]`) | |
| `targets` | `ReceptorTarget[]` | no (default `[]`) | |
| `pharmacokinetics` | object | no (default `{}`) | `halfLife?`, `clearance?`, `volumeOfDistribution?`, `bioavailability?`, `notes?` |
| `notes` | string | no | |
| `createdAt` / `updatedAt` | ISO 8601 | no | Filled by the importer when absent |

### `ReceptorTarget`

`id`, `name` required; the `id` must be unique within its drug (a
collision is rejected at import with the blocking error `DUPLICATE_ID`,
see validation.md §4); `gene?`, `action?`, `species?`, `kd?`, `ki?`,
`ec50?`, `ic50?`, `notes?` optional. `action` is an enum:
`agonist` \| `partial-agonist` \| `antagonist` \| `inverse-agonist` \|
`modulator` \| `reuptake-inhibitor` \| `unknown`.

**Kd, Ki, EC50 and IC50 are separate named fields.** The format makes it
impossible to "store a Kd" ambiguously.

## 4. Scientific parameters

Every parameter is an object — never a bare number:

```jsonc
{
  "value": 1,            // finite number; NaN/Infinity rejected
  "unit": "nM",          // non-empty string; validated against the unit catalog
  "provenance": {        // discriminated on "type"
    "type": "literature",
    "source": "...",
    "citation": "...",   // optional
    "doi": "...",        // optional
    "url": "...",        // optional, must be a URL
    "accessedAt": "...", // optional ISO 8601
    "notes": "..."       // optional
  }
}
```

Provenance variants: `literature` (requires `source`), `user`, `calculated`
(requires `model`), `derived` (requires `method` + non-empty `from`),
`unknown`. Full semantics: [provenance.md](provenance.md).

**Numbers stay numbers — including negative zero.** `value` is always a
JSON number, never a string, and must be finite: `NaN` and `±Infinity`
are rejected by the schema, not serialized. Negative zero is part of the
JSON number grammar (the token `-0`) and is preserved exactly through
the NPSL round trip: the application's serializer emits `"value": -0`
where a plain `JSON.stringify` would canonicalize it to `0`, the import
path stores the parsed sign unchanged, and an unrelated form edit keeps
both the sign and the parameter's complete provenance. This is proven by
round-trip tests over export, re-import, raw storage rows and form edits
(`npslDocument.test.ts`, `dexieDrugRepository.test.ts`, the drug-form
suites); no behavior of external tools beyond the JSON grammar is
claimed.

## 6. Evolution policy (how the format changes safely)

- **Known fields are strictly typed.** A wrong type (`value: "1"`, unknown
  provenance `type`, malformed date) is a hard validation error.
- **Unknown fields are preserved where storage can keep them.** Objects
  are parsed "loose": keys the current build does not know survive
  `parse → preview → import → storage → export` — at the drug record root,
  in `identifiers`, `targets[]`, in every scientific parameter and its
  `provenance`, in `pharmacokinetics`, and in `libraryMetadata`. Merge of
  an existing id resolves collisions deterministically: the incoming file
  wins a key, stored-only extension keys are kept (never silently
  discarded). The one exception: unknown keys at the *top level of the
  envelope* have no storage location — they are reported as warning
  `ENVELOPE_FIELDS_DROPPED` instead of being silently dropped. Covered by
  the repository round-trip tests (`dexieDrugRepository.test.ts`,
  "extension fields"), the mapper tests (`records.test.ts`) and the
  preview tests (`importPipeline.test.ts`).
- **Merge never overwrites a quarantined row.** One Merge case is refused
  outright: an incoming id that matches a stored row the schema considers
  invalid (quarantined on hydration) is a blocking `QUARANTINE_CONFLICT` —
  the whole document is rejected inside the import transaction before any
  write and the quarantined row stays byte-identical (audit GAP-3,
  `validation.md` §4).
- **Version gates decide readability** (§1). Newer-minor files are refused
  with guidance rather than half-imported.
- **Normalization is explicit and documented**: omitted collections default
  to empty arrays, `dataStatus` defaults to `unspecified`, missing
  `createdAt`/`updatedAt` are stamped at import time. Meaningful data is
  never dropped — only absent data is filled.

### Adding a field (checklist)

1. Add it to the Zod schema as `.optional()` (or with a default).
2. Add it to the domain type + mapper.
3. Bump `schemaVersion` minor.
4. Add a round-trip test asserting old files (without the field) still import
   and new files still export.
5. Document it here.

## 7. Relationship to the domain model

```
npslFileSchema (Zod, src/data/schemas/npsl.ts)
      │  import: parse → version check → schema → semantic checks → map
      ▼
domain Drug / DrugLibrary (src/domain/**)
      │  export: toNpslDocument → serialize (writes were schema-validated)
      ▼
.npsl file
```

Serialization types and domain types are deliberately separate: the file
format can evolve without leaking `optional`/`default` mechanics into the
domain, and the domain can gain derived fields without changing the format.
The mapping layer (`src/data/mappers`, phase 3) is verified by export →
import round-trip tests ([testing.md](testing.md) §7).
